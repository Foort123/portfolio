# Контекст для ИИ: проект KlourkStudio (портфолио фрилансера)

Скопируй этот текст целиком в начало диалога с любой другой нейросетью перед тем,
как просить её что-то изменить в этом сайте.

---

## Кто я

Я — фрилансер, разрабатываю сайты и продаю разработку на бирже **Kwork**
(kwork.ru/user/klourk). Этот сайт — **моё портфолио**, и оно же — моя главная
рекламная витрина: потенциальный клиент, открыв его, должен подумать
*«если он сделал такое портфолио — значит, мой сайт он тоже сделает на высоком
уровне»*. Поэтому качество кода, анимаций и дизайна здесь важнее, чем где-либо ещё.

## Что это за сайт

Одностраничное портфолио **KlourkStudio** — тёмная премиальная тема, стеклянные
карточки (glassmorphism), тёплый янтарно-оранжевый акцент, 3D-наклон карточек
под курсором, окно предпросмотра проектов в стиле Windows/браузера,
кастомная CSS-анимация «курсор строит сайт» в hero-блоке, scroll-reveal анимации,
магнитные кнопки и индикатор прогресса чтения.

**Технологии:** чистый HTML в одном файле `index.html`, Tailwind CSS через CDN
(`cdn.tailwindcss.com`), Google Fonts (Geist + Material Symbols), никакого
фреймворка/сборщика — весь JS вписан в `<script>` внизу файла. Хостится
статически (Railway / любой статик-хостинг).

**Структура файла:**
- `<head>`: конфиг Tailwind, кастомные CSS-переменные цветовой палитры (primary,
  secondary, surface и т.д. в стиле Material 3), затем большой `<style>` блок со
  всеми кастомными эффектами.
- `<body>`: навбар (fixed, стеклянный после скролла) → Hero-секция (заголовок +
  анимация «сборки сайта» + CTA-кнопки) → секция «Портфолио» с тремя категориями
  карточек (Сайты / Билборды / Превью) → модальное окно просмотра проекта
  (`#project-viewer`) → скрипты.
- Проекты хранятся в JS-объекте `PROJECTS` и открываются по `?p=<slug>` (шаринг
  прямых ссылок на проект).

## Что можно менять

- Тексты, заголовки, подписи, порядок карточек, добавление/удаление проектов.
- Цвета — **только в рамках текущей палитры**: тёмный фон (#080808/#131313),
  тёплый янтарно-оранжевый акцент (#ffb77f → #ff8a00, градиент до #ffdcc4).
  Не превращать сайт в светлую тему и не менять акцентный цвет на другой оттенок
  без явной просьбы.
- Анимации, микроинтерактивность, hover-эффекты — можно добавлять и улучшать,
  но **дополняя**, а не заменяя существующую систему (см. ниже).
- Вёрстку конкретных блоков (отступы, размеры, breakpoints) — по запросу.
- Добавление новых секций/интерактивных элементов, если они логично продолжают
  стиль «дорогого агентского сайта».

## Что менять НЕЛЬЗЯ без явного запроса

1. **Не ломать существующую систему эффектов**, если не просили её переделать:
   - `.tilt-card` / `.glass-panel` — 3D-наклон карточек за курсором через
     CSS-переменные `--tilt-x`, `--tilt-y`, `--glare-x`, `--glare-y`
     (JS в конце файла, `applyTilt`). Любые новые transform-эффекты на карточках
     должны сочетаться с этим (использовать те же CSS-переменные, не заменять
     `transform` напрямую).
   - `.reveal` / `.reveal-card` — scroll-reveal система (fade + подъём при
     появлении в вьюпорте), управляется классом `reveal-on` на `<html>`,
     выставляемым до первой отрисовки скриптом в `<head>`. Имеет hard failsafe
     (через 2.5с всё показывается принудительно) — **это защита от «пустого
     экрана», её нельзя убирать**.
   - `.magnetic` — магнитные кнопки, тянутся к курсору (только на устройствах с
     мышью, `hover: hover` и `pointer: fine`).
   - `#project-viewer` — модальное окно просмотра проекта с загрузчиком-анимацией
     «Собираем сайт», шарингом ссылки, полноэкранным режимом. Сложная логика,
     трогать только точечно.
   - `.hb-*` классы — кастомная CSS-анимация «курсор кликает и строит сайт»
     в hero-блоке (полностью на CSS keyframes, без JS). Очень тонко
     таймированная (курсор кликает точно по создаваемым элементам) — при
     правках сохранять синхронность.
2. **Уважать `prefers-reduced-motion`** — у каждого анимационного блока есть
   `@media (prefers-reduced-motion: reduce)` fallback, который отключает
   анимации, но не прячет контент. Любая новая анимация должна получить такой же
   fallback.
3. **Не добавлять backend/сборку** — сайт статический, один HTML-файл, без
   npm/webpack/React и т.п., если явно не попросят перейти на другой стек.
4. **Не удалять существующие проекты/работы из портфолио** без прямой просьбы.
5. **Не трогать структуру `PROJECTS` и логику `?p=slug`** (шаринг прямых ссылок)
   без явного запроса — это фича для отправки клиенту ссылки на конкретный кейс.
6. **Производительность важна**: код уже оптимизирован (rAF-троттлинг скролла,
   `will-change` только во время взаимодействия, без лишних repaint/reflow —
   в CSS есть комментарии, объясняющие такие решения). Не откатывать эти
   оптимизации ради «более простого» кода.
7. **Не превращать сайт в шаблонное портфолио** — цель: удивлять качеством,
   интерактивностью и вниманием к деталям (уровень agency/SaaS-сайтов), а не
   добавлять эффекты ради эффектов. Каждый новый интерактив должен усиливать
   ощущение профессионализма, а не быть «мишурой».
